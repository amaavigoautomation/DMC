# Destination brochures

The six-page destination PDFs are generated by `server/brochures.mjs` at download time. The public route is `/api/brochures/<country-slug>.pdf`. It checks the existing destination visibility setting before serving the PDF. There are no public static PDF files that bypass this check.

`npm run build` extracts brochure content from the fully rendered destination HTML using the same shared modules as the site. The plan headings and highlights come from actual country plan cards; unavailable plans are omitted. Prices, allowances and offers are intentionally not printed. The brochure links to the live plan section instead.

## New destinations

Follow the existing destination-page workflow: add the HTML, country content and the `common-destination-pricing` pageModules entry, plus breadcrumbs. The next build automatically registers the brochure, the download button and its entry on the Brochures page. No PDF needs to be authored or uploaded manually.

Optional country imagery is stored at `dist/img/brochures/<slug>.jpg`. These current images were derived from the existing website hero images. When no prepared destination image exists, the PDF uses the DMC24 product screen. This fallback allows future countries to download a complete brochure immediately. It does not invent a destination photograph.

## Maintenance

- Edit the page content and publish to update the content used in future downloads.
- Previously downloaded PDFs are snapshots and do not change.
- `node scripts/test-brochures.mjs` validates all country PDFs, download links, six-page counts, overflow limits and a new-country image fallback.
- `node scripts/verify-brochure-api.mjs` validates the download response and visibility restrictions.
- Set `BROCHURE_TEST_OUTPUT` to an absolute directory to export PDFs for design review. Do not commit those generated test files.
- Runtime needs the existing D1 and ASSETS bindings. Brochure generation does not write to the database.
